# Voxy 26.2 Vulkan Shader Contract Table

本文档冻结 `upstream/dev` 基线中正式 OpenGL shader 的输入、输出、变体、owner 和
Vulkan 表达方式。它不是新的渲染设计：表中的算法、buffer 布局、workgroup、draw 顺序和
分类全部以原 OpenGL owner 为准；Vulkan 只负责把相同合同表达成 SPIR-V、descriptor、
push constant、pipeline state 和显式同步。

状态含义：

- **已编译/反射**：该变体已在 Minecraft 26.2 实际 Vulkan device 上由 shaderc 生成
  SPIR-V，并通过 descriptor 与 push-constant reflection；不表示正式 owner 已接线。
- **基础设施已实现**：通用 pipeline/descriptor/lifetime owner 已存在并做过实际 device
  验证；不表示相应正式 render pass 已迁移。
- **正式 owner 待迁移**：仍由只读 OpenGL 基线 owner 描述行为，后续轮次必须逐项接入
  Minecraft Vulkan submission，不能以编译探针代替。

## 1. 全局 Vulkan GLSL 合同

### 1.1 Descriptor namespace

OpenGL 的 SSBO、UBO、sampler 和 image binding namespace 相互独立；Vulkan set 0 中
必须唯一。迁移层保留每种资源的原 binding 数字，并按下表确定性映射：

| 原资源类型 | 原 binding `n` | Vulkan set | Vulkan binding |
| --- | ---: | ---: | ---: |
| SSBO | `n` | 0 | `n` |
| UBO | `n` | 0 | `64 + n` |
| combined image sampler | `n` | 0 | `128 + n` |
| storage image | `n` | 0 | `192 + n` |

每个原 namespace 可用范围为 `[0, 64)`。shader reflection 与
`VulkanPushDescriptors` 在提交前要求 descriptor kind、binding 集合完全一致；任何缺失、
重复或错误类型都立即失败。当前 shader 的最大映射 binding 为 198，实际宿主
`maxPushDescriptors` 已在 pipeline layout 创建时验证。

### 1.2 普通 uniform 到 push constant

原 `layout(location = N) uniform TYPE name` 的 `N` 是 OpenGL uniform location，不是
字节 offset。迁移层在 shaderc 完成条件预处理后：

1. 按原 location 排序；
2. 按 std430 对应的 4/8/16-byte alignment 紧密打包；
3. 生成一个 `layout(push_constant, std430)` block；
4. 用 SPIR-V reflection 同时校验总大小和每个 member offset；
5. 多 stage graphics pipeline 中若两阶段均使用 push constant，则 layout 必须完全相同。

因此 location 中的空洞不会制造空字节，也不会让相邻 `mat4` 重叠。当前最大已编译合同是
SSAO 的四个 `mat4`，共 256 bytes；创建 module 时还会与宿主
`maxPushConstantsSize` 比较。

### 1.3 兼容性转换

| 原 GLSL 语义 | Vulkan 转换 | 保持的合同 |
| --- | --- | --- |
| `gl_VertexID` | `gl_VertexIndex` | 仍由 vertex/index/indirect draw 的同一编号驱动 |
| `gl_InstanceID` | `gl_InstanceIndex - gl_BaseInstance` | OpenGL instance ID 不含 base instance，而 Vulkan instance index 已含 firstInstance；shader 中显式 `gl_BaseInstance` 保持独立 |
| 缺少显式 stage location | shaderc `auto_map_locations` | 与 Minecraft 26.2 `GlslCompiler` 一致 |
| `gl_DepthRange.diff/near/far` | `1/0/1` 常量 | Minecraft 26.2 Vulkan viewport 固定 `minDepth=0,maxDepth=1` |
| `IS_INTEL` | physical-device vendor `0x8086` | 保留原 subgroup workaround 分支 |
| `IS_WINDOWS` | 当前 OS | 保留原 prefix-sum 平台分支 |
| shader `printf` 且 debug 关闭 | 原 `PRINTF_processor` 删除诊断调用 | 保留正式非 debug 算法 |
| shader `printf` 且 debug 开启 | fail-fast | Vulkan printf 尚未迁移，不静默改写行为 |
| terrain `GL_ARB_gpu_shader_int64` 自动分支 | 明确选择原 `ivec2` quad 路径 | 不把 `shaderInt64` 新增为硬能力，不改变 8-byte quad 数据 |

正式 Vulkan terrain pipeline 通过 `QUAD_DATA_USE_IVEC2` 显式选择原 shader 已有的
`ivec2` 分支；该分支仍按两个 32-bit word 解释同一条 8-byte quad record。shaderc 后的
SPIR-V reflection 会拒绝任何声明 `Int64` capability 的正式 shader，防止后续改动重新把
`shaderInt64` 变成隐藏硬要求。

`RenderProperties.shaderDefines` 的 `USE_ZERO_ONE_DEPTH` 与 `USE_REVERSE_Z` 仍是所有相关 stage 的
共享 define。任何 TAA、Iris patch 或 directional tint define 必须同时应用到原来共享它的
vertex/fragment stage，不能只改一侧。

顺序会让未激活的分支产生伪 descriptor 或重叠 push member。

## 5. 已验证证据与未完成边界

2026-07-15 在 Minecraft 26.2 实际 Vulkan backend、NVIDIA GeForce RTX 5070 Ti 上完成：

- 全部正式非 Iris base compute/vertex/fragment 变体，以及上述无 caller 资源，均成功生成
  SPIR-V 并通过 descriptor、push-constant size/member-offset reflection；
- `post/fullscreen.vert + post/noop.frag` 创建了实际 dynamic-rendering graphics pipeline，
  证明 graphics pipeline/cache/layout 基础设施可在宿主 device 创建和延迟销毁；
- `util/set.comp` 实际 dispatch/readback 通过；geometry memcpy/scatter 的完整 section
  metadata 与 8-byte elements 逐字节一致；
- 临时 inventory/graphics/geometry probes 均已删除，日志中未发现 Vulkan validation VUID。

仍未完成且不得据此勾选 renderer readiness 的项目：

- HOC、NodeCleaner、HiZ、MDICViewport、MDIC renderer 和 base terrain 已接入单一前半帧
  源码链，但完整 renderer gate 仍关闭，且尚缺实际 device pipeline/descriptor validation；
  SSAO、translucent frame pass 与 composite owner 仍未建立；
- 原 GPU 顺序对应的精确 `vkCmdPipelineBarrier2`、indirect dispatch、
  `vkCmdDrawIndexedIndirectCount` 和 dynamic-rendering attachment 接线；
- shader/resource reload 的 pipeline replacement 与在途 submission retirement；
- Iris 1.11.2 shader patch、TAA、shadow/deferred/composite 合同；
- 真实世界视觉、跨 GPU/driver、resize/reload/unload 和长时间压力验证。
